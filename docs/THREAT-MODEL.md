# Threat model

GhostLink limits what a pocket session can authorize; it does not make a page safe to receive the master identity secret or guarantee private funding. This is a source-level threat model, not an independent audit or an assertion that a deployed program contains these changes. Each row names a threat, its control or remaining trust requirement, and relevant coverage. Re-read at every milestone gate.

| Threat | Control | Lives in | Tested by |
| --- | --- | --- | --- |
| App asks the main wallet to sign an unsafe transaction | The SDK and wallet facade expose no main-wallet transaction-signing method. Other page code can still ask a wallet to sign; setup and recovery use message signatures, and wallet-funded deposits require transactions | SDK, host integration, wallet UI | SDK facade feature-surface tests; phishing resistance remains a user/host responsibility |
| Phishing page asks the user to connect their real wallet | Cannot be prevented by an SDK; mitigated by making the real wallet unnecessary, partner-app education | Product, marketing | — (human) |
| Phishing page or Actions endpoint substitutes a funding transaction | `fundingOptions` re-derives the PDA; `verifyFunding` checks metadata only. `prepareFundingTransaction` checks every byte of the supported unsigned legacy deposit structure against independently approved wallet/app/asset/amount and substitutes a trusted blockhash. Only sign its returned bytes after independent chain/state/fee/rent checks and consent | Actions endpoint, SDK, funding wallet | SDK `funding.test.ts`: substitutions, extra signers/instructions, permissions, malformed encodings, single-byte tampering and detached buffers; installed consumer and real local-validator SOL/SPL deposits. Metadata alone is insufficient |
| Called program forwards the pocket's signer privilege | PDA signing is confined to fixed SPL Token transfer/close instructions, never forwarded to solver-selected programs; every `invoke_signed` call site lives in `token.rs` | Pocket program | `programs/itests` fill flows; source review of `token.rs` |
| Solver takes the input and never delivers | `fill_end` reverts the whole transaction; `fill_begin` refuses without a matching `fill_end` later in the same transaction | Pocket program | `fill_flow_and_refusals`: underfill atomic revert, NoFillEnd, FillInterleaved |
| Solver fakes delivery with a second pocket-owned token account it pre-seeded | `fill_end` measures the balance delta on the very account `fill_begin` snapshotted (`FillState.out_account`) | Pocket program | `fill_flow_and_refusals`: FillAccountMismatch case |
| Malicious app sets `out_min` near zero | Oracle floor for priced trades; unpriced trades require explicit bounded consent and tracked exits. A compromised approved session can lose its permitted speculative budget | Pocket program | SlippageFloor and NoOracleViolation cases |
| Stolen software session key | Daily cap, session expiry, big-action threshold and no direct pay-out instruction limit authorized spending. Losses within those limits remain possible; recovery needs the identity secret and transaction submission access | Pocket program, SDK | DailyCap/PasskeyRequired/SessionExpired cases; sweep + revoke flows |
| Stolen device with passkey | Passkey assertions require user presence and user verification. The host must protect any stored identity secret; the SDK does not automatically encrypt or persist it | Host/device, pocket program | WebAuthn UP/UV flag checks; physical authenticator and storage posture require separate review |
| Proof presented for another domain or session | Public inputs bind the domain and session commitment; the verifier checks the expected domain and the program re-derives session/home commitments. This does not isolate raw secrets from page scripts | Circuits, programs, verify | wrong-session-key refusal; verification-key IC binding tests; verify domain/session tests |
| Relayer substitutes the first pocket's policy, or reuses a website login as spending consent | V2 re-derives a proof-bound context from purpose, all three program IDs, canonical policy hash and session kind; creation uses the approved initial policy and renewal uses stored policy. Off-chain verification defaults to login-only context zero | Circuit, Pocket, SDK, verify | `first_session_binds_policy_purpose_and_deployment`; SDK policy mutation and backend purpose/deployment tests. Localnet candidate only; V1 remains deployed |
| Captured `open_session` resent to reinstate a revoked session | Every new session must expire later than every earlier one (`max_session_expiry_slot`), so a resend is refused | Pocket program | `revoked_session_cannot_be_replayed` |
| Consumed owner authorization replayed after a later change | Sweep/revoke/propose/cancel digests bind the current `owner_action_nonce`; successful administrative actions and `execute_change` advance it. Callers must read current state before proving | Pocket program, SDK | `sweep_changes_and_revoke`; SDK action-digest fixtures and nonce regression |
| Stale or invented roots and census snapshots | Programs accept ring roots and enforce claim freshness. SDK witness checks establish consistency with supplied roots only. Off-chain verifiers need trusted roots and server-chosen `expect.minSlot` for a fresh holdings claim | Programs, SDK, verify | UnknownRegistryRoot case; SDK tampered-witness and bounded-pagination tests; verify unknown-root/minSlot tests |
| Fake precompile instruction | Introspection checks program id, key bytes, message bytes and offsets, never mere presence | Programs | WrongSigner/WrongMessage/MissingSignature cases |
| CPI-wrapped `fill_begin` to bypass introspection | `get_stack_height() == 1` on every state-changing instruction | Pocket program | `cpi_wrapped_instructions_are_refused` (register, fill_begin, revoke, sweep through `programs/cpi-caller`) |
| High-S P-256 signature rejected or raw bytes mistaken for DER | Normalize to low-S client-side; recognize compact 64-byte signatures even when their first byte is `0x30`; precompile rejects high-S | SDK (`normalizeDerToLowS`) | SDK DER, raw-signature and real P-256 regressions; `p256_requires_explicit_unpriced_permission` |
| Invalid or non-deterministic wallet signature becomes an unrecoverable identity | Verify both signatures against the fixed message and requested wallet, then compare determinism. Random-secret fallback requires explicit opt-in and an independently protected backup; the dashboard does not enable it | SDK | invalid signer and real hedged-signer regressions |
| Registration spam fills the tree | Relayer rate limits + 0.01 SOL balance check; depth-26 tree | Relayer | `RateLimiter` logic; balance check in `/register` |
| Census double counting across wallets | Documented limitation; apps use `min_slot` windows and one claim per `app_id` | Docs, SDK | — (documented, no stronger promise made) |
| Tiny anonymity set early on | Privacy claims stay modest below 10,000 registrations; SDK can show the set size (`nextIndex`) | Marketing, SDK | — (copy rule) |
| Program upgrade by an authorized party or compromised authority | A live upgrade authority remains a trust dependency. Removing it after independent review is a planned mainnet gate, not a property established by this source tree | Deploy process | Deployment-specific authority inspection required; no completed mainnet removal claimed |
| Mistyped or missing relayer state silently resets spending history | Hosted startup requires an authenticated existing database, existing operations schema and independently pinned encrypted journal ID. Initialization generates a fresh payer and state exclusively in a new directory. Legacy or restored state cannot enter hosted paid work | Relayer startup and shared storage | Real startup regression refused missing/empty/different/damaged state and preserved the original packet/charge on valid restart; initializer and retained-history drills. Authentic manual rollback still requires independent reconciliation |
| Missing or substituted solver journal forgets exact submissions and nonce ownership | Hosted startup requires authenticated existing history/context/recovery tables and an independently pinned encrypted instance ID. Explicit initialization generates a fresh solver payer in an exclusive new directory. Legacy maintenance cannot transact; restored state retains owner-session quarantine | Solver startup and submission journal | Actual-process startup regression, preserved packet/nonce/context restart, marker-loss refusal, fresh initialization and restored-pin/key-rotation checks. Authentic same-journal rollback still requires independent history reconciliation |
| Missing watcher state replays notifications or resets crank fee history | Hosted startup requires authenticated existing observation and optional fee-journal stores with separate instance pins. Missing checkpoint/progress/spending records are errors. Initialization generates a new observer or fresh funded payer in an exclusive directory; wrong state pins are refused before lease acquisition | Watcher state, crank journal and startup | Real missing-state and deleted-spending regressions, observer/funded initializer/process checks, preserved delivery acknowledgment and cumulative-fee records. Authentic rollback and coordinated migration remain separate gates |
| An older relayer backup omits already paid work | Every supported restore gets an authenticated quarantine epoch. Maintenance can inspect/reconcile retained signed packets and rotate storage keys, but claim, preparation, submission and hosted startup stay disabled. All reports explicitly leave history completeness and paid resumption unapproved | Relayer journal and operator tooling | File-backed old-snapshot/rotation/CLI regressions; local-validator retained-history reconciliation without payer key or debit. Full missing-operation reconciliation and controlled cutover remain gates |
| Missing indexer checkpoint or spool rows silently erase derived history | Hosted startup requires authenticated existing schema and an independently pinned instance ID. Required snapshot/progress/scan records cannot be defaulted; authenticated spool counts detect missing rows before application, completion and readiness. Explicit fresh rebuild initialization is separate from startup | Indexer database, poller and startup | Deleted-snapshot and spool-row regressions; real startup/initializer, restart, restore refusal and Unix drain checks. Counts and pins do not prove archival completeness or detect authentic same-database rollback |
| Relayer or indexer compromise | On-chain operations still enforce proof/ring checks. Services can deny liveness and correlate requests. An indexer supplied as the off-chain verifier's root source is also trusted for integrity; use a trusted on-chain ring reader to remove that dependency | Architecture, application backend | indexer chaining tests; verify unknown-root tests. These do not prove an arbitrary remote root source honest |
| Forged event in logs (any program can emit a byte-identical `Program data:` line) | `decodeLogs` attributes events by invoke/success framing: rightful program, depth 1 only | service-kit | `kit.test.ts`: wrong program, CPI depth, trailing frame all refused |
| Unauthenticated, late or replayed webhook poisons the indexer | Hosted webhooks require the shared secret and only request ordered finalized polling. Bounded durable pagination preserves same-slot order; state, cursor and dequeue commit atomically. Missing logs/history refuse progress; owned state and head freshness gate readiness. Clients still verify roots independently | Indexer | [Operations and limits](INDEXER-OPERATIONS.md); missing-log/page regressions, SQLite rollback, process exit/restart, ownership fencing, readiness and Unix drain drills |
| Funding builder uses the wrong chain, stale accounts or unsafe token destination | Approved-genesis RPC and headers, contextual full Pocket/mint/token-account validation, monotonic context floor and readiness; canonical unsigned instructions only. Clients still validate the actual transaction and simulate before signing | Actions service and funding wallet | [Actions operations](ACTIONS-OPERATIONS.md); wrong-chain/stale/context-race regressions, real process fallback/drain and complete local-validator token/native deposit and recovery |
| Registered identity drains the relayer with repeated or concurrent requests | Actual fee/rent budgeting and atomic payer-liquidity reservations, cached readiness, bounded admission, per-IP/wallet limits and optional partner-domain allowlist; initialized-account checks stop prefunded system PDAs bypassing creation controls. Require the scoped persistent journal across restarts | Relayer | `journal.test.ts`, `server.test.ts`, `operations.test.ts`: concurrent funding/fees, covered finality, ambiguous broadcast, dependency refusal and prefunded-PDA cases |
| Intent asks the solver to deliver more than it receives (`inMax: 0`) | Priced inventory valued against configured feeds; unpriced legs off by default and allowed only through intent-funded routes plus owner policy | Solver | `economics.test.ts` |
| Phishing page obtains the fixed identity-message signature | The message names the configured identity domain, but wallet warnings vary and are not a hard block. An optional PRF factor makes the wallet signature alone insufficient; without it, the signature reproduces the identity secret | SDK, dashboard | sign-in text, native/plain equivalence and factor tests; real authenticator behavior is manual |
| Raw identity or wallet witness given to an untrusted page | No SDK sandbox prevents that page from reading them or deriving every app ID. Keep them in a separately trusted execution context; an isolated cross-origin broker is not included | Host application/integration | Explicit architectural limitation, not a control provided by `GhostLink.origin()` |
| PRF creation fallback uses an older credential | Restrict the immediate PRF assertion to the newly created passkey's ID; recovery still requires the original PRF-capable credential | SDK | PRF credential-selection regression with a mocked authenticator; hardware interoperability remains manual |
| Old signed intent resurfaces after the nonce window moves | Sliding window: values below `nonce_base` read as used forever; a jump forward clears what it retires | Pocket program | `nonce_window_slides`, `state::nonce_window` unit test |
| User without SOL cannot apply their own timelocked change | A running watcher with a funded fee payer can crank `execute_change` once due. The entry point requires an approved chain and an exclusively owned encrypted alert queue, durably acknowledges stable alert IDs, commits a scoped encrypted packet and cumulative fee reservation before sending, preserves identity across restart and verifies its own transaction acknowledgment; receiver/service availability remains required | Watcher | [Operations and remaining gates](WATCHER-OPERATIONS.md); crash/restart, competing reservations, expiry, fee limits, wrong acknowledgment, write refusal and webhook tests; validator lost-acceptance recovery, fee reconciliation and real owner cancellation |
| Captured off-chain login proof reused as a bearer token | `verifyLogin` checks proof/session binding and expiry but does not authenticate nonce possession. Backend must verify a signature over `loginChallengeDigest` for its own fresh nonce and atomically consume that nonce before issuing a session | verify, SDK custom wallet feature, application backend | verifier binding/expiry tests; custom-wallet signed-challenge regression. Application nonce storage/consumption needs integration testing |
| Malformed public input or numeric expectations escape backend verification | Canonical bounded field strings, byte lengths, u64 slot/threshold validation and fail-closed malformed-input results | verify | null/object/oversized input, NaN threshold and field-sized slot alias regressions |
| Hostile relayer sets a permissive policy at pocket creation | V2 opening proofs bind purpose, deployment, initial policy and session-key kind; renewal uses the stored policy. Intents also commit to the policy hash | Pocket program, circuits, SDK | Initial-policy substitution, wrong-purpose/deployment proofs, policy-hash mismatch and complete local-validator checks; independent review remains required |
| Recovery relayer selects a home-owned account with outside authority | Sweep rejects destination delegates and external close authorities on-chain. Automatic relayer recovery creates a clean home-owned account when the canonical destination is unusable | Pocket program, relayer | Compiled-program refusal/rollback regression; real SPL owner/delegate/close-authority changes and complete automatic recovery in the validator drill |
| Tampered proving artifacts or reused cache entry | Hash checking is enabled only when callers supply trusted `wasmSha256`/`zkeySha256` values. Cache entries are scoped to URL and expected hash. Package provenance and release verification remain separate controls, not guarantees from this loader | Host configuration, prover-wasm, release process | `prover.test.ts`: conflicting cached pins, malformed pins, retry and concurrent download reuse |
| Prover or storage integration exposes secret inputs | Proving receives the raw identity/wallet witness and runs in the caller's context; no worker, remote privacy boundary or encrypted persistence is created automatically. Keep proving local and protect host storage | Host integration | Source-level API contract; integration/device review required |

## Review cadence

- Every PR touching `programs/` or `circuits/` needs a second reviewer and a passing invariant suite (CI enforces the suite; the reviewer rule is process).
- A bounty scoped to programs, circuits and SDK is planned for M4; do not present that plan as an active program without published launch terms.

PocketV3 speculative accounting, loss-taking semantics, policy transitions and remaining review gates are specified in [ADR 0004](adr/0004-bounded-speculative-trading.md). Acquisition-cost exposure is not mark-to-market risk.

Recovery also handles token accounts transferred to the pocket while retaining a foreign close authority. New fills refuse such output accounts. A sweep still transfers their entire token balance home and leaves the empty account for its close authority; failure to reclaim rent cannot block token recovery. Two real SPL `SetAuthority` regressions reproduce the original withdrawal failure and verify the fix.

The recovery home's canonical account is also validated; address derivation alone does not establish current ownership or control. [Automatic recovery destinations](OWNER-RECOVERY.md) describe fallback account creation, spend limits, confirmation and lost-response handling. This does not extend support to frozen sources or Token-2022.
